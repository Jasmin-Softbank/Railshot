# 검증 결과

검증일: 2026-10-02 (한국 시간)

판정: **초기 구현의 오프라인 검사 통과. 실제 배포 및 운영 인수는 미완료입니다.** 구현 에이전트 3개가 코드를 작성하고, 본 세션은 코드 검토·수정 요청·독립 검사와 이 기록 작성을 담당했습니다. 실제 서버는 변경하지 않았습니다.

## 독립 검사 환경과 결과

- macOS 실행 호스트, Python 3.11.15, ansible-core 2.19.13, ansible-lint 26.9.0, pytest 9.1.1.
- `ci/scripts/check-ansible.sh` 최종 실행 종료 코드 0.
- 실행 플레이북 9개 문법 검사 통과.
- Ansible 작성 규칙 검사: 61개 파일 검사, 규칙 위반 0건. 공통 입력 변수의 역할 접두사 규칙만 명시적으로 제외했습니다.
- 기본값 및 암호화 검증 해제 방지 정적 계약 검사 통과.
- 실제 Ansible을 로컬 시험 경로에서 실행하는 자동 시험 15건 통과.
- 시험 구성: 입력 검사 6건, 설정 생성 및 생성된 셸 스크립트 문법 검사 9건.

입력 시험은 기본 동기 복제, 서버 목록 변수에서 비동기로 변경, 클러스터 이름 누락, 중복 주소, 잘못된 복제 정책, etcd 노드 수 부족을 검사합니다. 실패 사례는 변경 없이 중단되는지 확인합니다.

설정 시험은 etcd 구성원·상호 인증, HAProxy 데이터 연결과 상태 검사 연결의 분리, 인증서 이름 검사, Patroni 동기·비동기 설정, 특수문자가 포함된 시험 비밀번호 보존, 필수 주소 누락 시 출력 미생성, 백업 보관 개수 변경 및 생성된 백업 스크립트 문법을 검사합니다. 실제 서비스 바이너리를 실행한 검증은 아닙니다.

예시 서버 목록에 복원 대상 그룹이 없어 문법 검사 시 해당 그룹 경고가 발생합니다. 복원 작업을 실행한 것은 아닙니다. 검사기의 경로 안내와 오프라인 의존성 설치 생략 안내도 발생했으며, 작성 규칙 위반과 구분했습니다.

## 검토 중 수정한 주요 사항

- 기존 데이터 소유권 표시 파일의 경로와 내용을 역할 사이에서 통일했습니다.
- 기본 설정이 서버 목록의 사용자 선택을 덮지 않도록 역할 기본값으로 옮겼습니다.
- 검증 SQL의 YAML 따옴표 오류와 백업 보관 개수 변수 불일치를 수정했습니다.
- 기존 etcd의 다른 클러스터 소유권 및 무단 설정 변경을 차단했습니다.
- 데이터 경로의 심볼릭 링크·별칭과 백업 경로 중첩을 차단했습니다.
- 지원 포트 및 관리 계정, 인증서 이름 조건을 명시했습니다.

경로 보호 코드는 최종 문법·작성 규칙 검사와 코드 검토를 거쳤으나, Ubuntu에서 실제 파일·마운트·서비스를 대상으로 한 실행 검증은 아직 수행하지 않았습니다.

## 미검증 및 제한

실제 Ubuntu 서버, 인증서, 네트워크, 백업 저장소가 제공되지 않았고 로컬 Docker 실행 엔진도 동작 중이 아니므로 아래 항목은 수행하지 않았습니다.

- 패키지 설치, 서비스 기동 및 전체 배포 재실행의 실제 멱등성.
- 실제 인증서 유효성·상호 통신, HAProxy 바이너리의 설정 해석과 중계 접속.
- PostgreSQL 실제 복제·동기 정책, 장애 전환, 네트워크 단절, etcd 과반수 상실.
- 백업 생성, 복원 후 변경 기록 적용, 데이터베이스 기동 및 SQL 데이터 비교.
- Prometheus 경보 및 Grafana 대시보드의 실제 수집 환경 연결.

현재 백업은 기본 비활성화이며, 활성화해도 노드별 로컬 저장소 방식입니다. 주 서버 교체 전후의 백업·변경 기록을 하나로 복구하는 설계는 포함하지 않았습니다. 복원 플레이북은 격리된 빈 경로에 파일을 복구하는 단계까지만 수행하고 데이터베이스를 기동하지 않습니다.

단일 Patroni 클러스터의 기존 가상머신 배포가 구현 범위입니다. 독립 대기 클러스터, 클라우드 자원 생성, 대시보드 실행 연동, 운영 중 순차 업데이트, 공통 접속 주소의 이중화는 포함하지 않았습니다. 예시 중계 서버 하나는 단일 장애점입니다.

## 재현

지원되는 Python 3.11~3.13의 격리 환경에 `ci/requirements-dev.txt`를 설치하고 저장소 루트에서 실행합니다.

```bash
bash ci/scripts/check-ansible.sh
```

실제 환경 인수는 `validation-plan.md`의 시험을 수행하고 결과를 추가한 뒤 별도로 판정해야 합니다.
