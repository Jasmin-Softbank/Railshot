# RAILSHOT 발표·통역 스크립트 초안

2026-10-02 · 한국어 초안 · 발표 언어/발표자 최종 선택 전 · 미제출

이 문서는 최종 발표와 순차 통역을 준비하기 위한 한국어 원고입니다. 발표 시간은 설명 약 2분과 실제 데모 약 3분이며, 통역 시간을 제외합니다. [기획서](proposal.md)와 [아키텍처](architecture/README.md)를 화면에 열고 필요한 구간을 보여줍니다. 발표 형식과 기한은 [제출 안내](submission-requirements.md)를 참고하세요.

대괄호 항목은 리허설 결과로 채웁니다. 현재 두 target의 실제 배포 결과는 확보하지 못했습니다. 실행 결과를 채우기 전에는 성공을 설명하는 문장을 사용하지 않습니다. 목업·과거 실행·녹화 화면에는 해당 상태를 표시합니다.

## 발표 전 확정할 값

| 항목 | 리허설에서 기록할 내용 |
|---|---|
| 발표 언어·발표자 | [한국어/일본어 확정, 설명/데모 담당] |
| 문서·코드 판본 | [통합 commit, 검사 보고 링크, 보여줄 문서 위치] |
| 앱 입력 | [샘플 이름, source SHA, 지원 profile, 기대 응답 내용] |
| 대상 | [AWS target ID/CPU, OpenStack target ID/CPU] |
| 이미지 | [target별 실제 digest. CPU/profile이 다르면 동일 digest라고 하지 않음] |
| 공개 접근 | [AWS URL, on-prem URL, 외부 클라이언트 확인 시각] |
| AI 관측 | [기본 실패, 허용된 수정, 재검사 결과가 남은 실제 run] |
| 시간 | [환경 준비/CI/CD/외부 HTTP 각 소요 시간, 현장에서 보여줄 실행] |
| 현재 한계 | [완료한 범위, 남은 연결, 목업/녹화 사용 여부] |

## 최종 발표 — 설명 약 2분

### 0:00–0:30 · 무엇을 만들었는가

화면: 기획서 첫 문단.

“RAILSHOT은 로컬에서 만든 웹앱을 AI의 도움으로 준비하고, 선택한 클라우드나 온프레미스에 배포하는 시스템입니다. 웹 화면, CLI, MCP에서 같은 배포 기능을 사용하도록 만들고 있습니다.”

“환경의 최초 등록과 권한 준비는 한 번 수행합니다. 그 뒤에는 앱을 제출하고 준비된 대상을 선택해서 배포를 시작하는 경험을 목표로 합니다.”

[순차 통역을 기다립니다.]

### 0:30–1:00 · 왜 이 문제를 골랐는가

화면: 기획서 문제 설명과 사용자 흐름.

“로컬에서 잘 실행되는 앱도 다른 환경에 옮기면 빌드 설정, 포트, 실행 환경과 네트워크를 다시 맞춰야 합니다. 그리고 빌드가 성공해도 사용자가 접속하지 못할 수 있습니다.”

“그래서 앱을 검사하고 준비하는 공통 과정과, 환경마다 다른 인프라·네트워크를 나눴습니다. 마지막에는 선택한 대상에서 어떤 버전이 실행되고 실제 URL에 접속할 수 있는지 확인하도록 설계했습니다.”

### 1:00–1:30 · AI가 실제로 하는 일

화면: 데이터 흐름과 실제 gate 기록.

“먼저 기본 검사를 합니다. 수정 가능한 실패가 나오면 AI가 허용된 범위에서 설정이나 코드를 수정하고 같은 검사를 다시 실행합니다.”

“검사를 통과한 이미지는 다시 빌드하지 않고 그대로 게시합니다. 배포할 때는 변하지 않는 이미지 식별값인 digest로 고정합니다. AI의 설명, 검사의 판정, 실제 배포 상태를 구분하는 것이 핵심입니다.”

[실제 AI 실행 기록이 있으면 해당 검사와 수정 결과를 보여줍니다.]

### 1:30–2:00 · 환경과 팀의 책임

화면: 전체/클러스터 그림 중 한 구간.

“RAILSHOT 운영 영역과 고객 앱 실행 영역을 분리했습니다. AWS와 OpenStack도 각각 독립된 K3s 클러스터를 사용합니다. 두 환경은 같은 runtime 설치 부품을 재사용하고 환경 준비와 공개 접속 경로는 각각 맞춥니다.”

“팀은 사용자 진입, AI·CI, Provider, Ansible 연결, runtime으로 책임을 나눴습니다. CD는 회의에서 Argo CD로 우선 진행하기로 했으며, 다른 방식의 조사도 병행합니다. 이제 실제로 확인한 범위를 보여드리겠습니다.”

## 최종 발표 — 데모 약 3분

아래 시간은 진행 목표입니다. 리허설에서 빌드·게시·적용 시간을 측정하고, 현장에서 보여줄 구간을 정합니다. 미리 준비한 단계와 현장에서 실행한 단계는 구분해서 설명합니다.

| 구간 | 화면·행동 | 말할 내용과 확인 조건 |
|---|---|---|
| 2:00–2:25 | 준비된 AWS/OpenStack target과 샘플 소스 표시. 실제 배포 요청 | “이 앱은 [기대 기능]을 보여주는 샘플입니다. 대상 환경은 미리 준비했고, 지금 [target]에 배포를 요청합니다.” 최초 환경 준비를 방금 한 것으로 말하지 않음 |
| 2:25–3:00 | 실행 식별자와 gate/AI 기록 확인 | “지금 보고 있는 실행은 [run]입니다. [실제로 관측된 검사/수정]을 거쳐 [판정]이 나왔습니다.” 로그·attempt가 지금 실행과 같은지 확인 |
| 3:00–3:35 | 게시 digest와 대상 적용 revision 연결 | “검사한 이미지가 이 digest로 게시되었습니다. 현재 대상에는 [실제 revision과 상태]가 보입니다.” 게시만 되었으면 아직 배포 완료가 아니라고 말함 |
| 3:35–4:15 | 다른 target에도 실제 배포 요청·진행·적용 확인 | “같은 앱을 [다른 target]에 배포합니다. [공통 부분]은 재사용하고 [환경별 차이]를 이 연결에서 처리합니다.” 같은 CPU/profile일 때만 동일 digest 재사용이라고 말함 |
| 4:15–4:45 | 외부 브라우저/클라이언트에서 두 공개 URL 확인 | “이 주소는 AWS의 앱이고, 이 주소는 OpenStack에서 실행되는 앱입니다. 각각 [기대 응답]을 확인했습니다.” 실제 두 응답 확인 시에만 사용 |
| 4:45–5:00 | 실제 완료 범위·한계 한 문장 | “오늘 확인한 범위는 [증거 있는 범위]입니다. [남은 항목]은 다음 검증 대상으로 남겨두었습니다.” |

실패가 발생하면 중단된 단계와 확인한 결과를 설명합니다.

“이번 실행은 [실패 단계]에서 중단되었습니다. [게시/클러스터 적용/공개 접속]까지는 아직 확인되지 않았습니다. 남은 오류와 실행 근거를 이 화면에서 확인할 수 있습니다.”

목업이나 과거 기록을 보여줄 때는 화면의 출처를 먼저 설명합니다.

“이 화면은 [mock/이전 실행/녹화]입니다. 현재 실행의 성공 근거로 사용하지 않고 [구조/실패 처리/검사 항목]을 설명하기 위해 보여드립니다.”

## 통역용 기술 용어

| 용어 | 원고에서의 뜻 |
|---|---|
| RAILSHOT | 이번 팀의 배포 지원 제품 이름. 발음은 팀 발표자가 확정 |
| One Action, Infinite Clouds | 최초 준비 뒤 반복 앱 배포를 단순하게 한다는 공식 테마와 제품 방향 |
| MCP | AI 클라이언트가 정해진 기능을 호출하는 연결 규약. 현재 구현은 로컬 stdio |
| CI / gate | 앱을 빌드·검사하고 통과 여부를 판정하는 과정. 배포 완료 판정과 구분 |
| image digest | 게시한 컨테이너 이미지를 정확히 지정하는 내용 기반 식별값 |
| Argo CD | Git에 기록한 배포 선언을 Kubernetes에 동기화하는 도구. 현재 임시 진행 기준 |
| K3s / Cilium | Kubernetes 배포판 / 해당 클러스터의 네트워크 구성 요소 |
| OpenStack Provider | 기존 OpenStack의 VM API를 제품에서 호출하도록 감싸는 팀의 구현 |
| Route 53 / ALB | DNS 이름 해석 / AWS의 HTTP·HTTPS 요청 분배. Route 53이 HTTP를 중계하지 않음 |
| WireGuard / EIP | 암호화된 L3 관리 연결 / EC2 종단에 연결할 고정 public IPv4 |
| Patroni | PostgreSQL 운영·고가용성 구성을 위한 검토 대상. 이번 통합의 HA 완료 주장 아님 |
| unscoped token | project 범위가 없는 OpenStack 인증 token. 허용 project의 scoped token으로 교환 가능하므로 인증 비밀로 취급 |

이 원고는 한국어 초안입니다. 발표 언어와 담당자를 확정하고 리허설 결과를 반영한 뒤 제출합니다.
