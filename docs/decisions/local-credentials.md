# 로컬 인증정보 보관 결정

설치 시 OpenStack 관리자 ID와 암호를 고객 터미널에서 받아 전용 계정·프로젝트 역할과 애플리케이션 자격증명을 생성합니다. 관리자 암호, 전용 계정의 초기 난수 암호, 임시 토큰은 디스크에 저장하지 않습니다. 범위 미지정 토큰만 영구 저장하는 방식은 토큰 만료 때문에 채택하지 않았습니다.

장기 자격증명은 cryptography Fernet 인증 암호화로 로컬 저장합니다. 생성된 암호화 키도 같은 고객 노드의 root 전용 파일에 저장하는 기본 구현입니다. 자동 재시작이 가능하지만 root 권한 탈취나 노드 전체 백업 탈취까지 방어하지 못합니다. 하드웨어 키 보호, 외부 키 관리 서비스, 운영 중 자동 교체는 구현하지 않았습니다.

서비스 등록 요청에 OpenStack 인증정보는 포함되지 않습니다. OpenStack 인증 요청은 고객의 Keystone에만 보냅니다. Python 메모리의 비밀문자열을 안전하게 소거한다고 보장하지 않습니다. 고객 운영체제의 메모리 덤프·관리자 권한·백업 정책도 필요합니다.

자격증명 폐기는 고객 OpenStack에서 수행해야 합니다. 같은 이름의 기존 사용자는 설치 소유권이 없으면 자동 인수하지 않습니다. 부분 설치 실패에 대한 자원 식별자만 상태에 남기며, 상태 파일을 삭제하기 전 정리 여부를 확인해야 합니다.

OpenStackClient 호출 중에는 고객 노드의 0700 임시 디렉터리에 0600 clouds.yaml을 만들어 자격증명을 일시적으로 평문 제공하고 호출 후 제거합니다. 이는 메모리만 사용하는 보관 방식이 아니며, 디스크 안전 소거나 비정상 프로세스 종료 후 자동 잔여파일 정리를 보장하지 않습니다.
